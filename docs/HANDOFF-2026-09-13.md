## 1. 这个项目是什么

一个仓库里有两套东西：

| 部分 | 内容 | 技术栈 |
|---|---|---|
| **桌面版**（根目录） | `video_downloader.py`（tkinter，README 里写的那版）、`video_downloader_qt.py`（PySide6「Fluent 版」，`启动视频下载器.bat` 启动的是它）、`error_diagnosis.py`（失败诊断）、`export_cookies.py`（Chrome Cookie 解密导出） | Python + `tools/yt-dlp.exe` |

## 2. 安卓版当前功能（本会话做完的）

- **底部导航三标签**：首页 / 下载 / 更多（视觉对标 YTDLnis）
- **首页**：品牌色大字标题 → 填充式胶囊输入框（左粘贴 / 右抓取）→ 结果卡（缩略图铺满 + 渐变压暗 + 白字压在图上 + 右下两个圆形按钮）→ chip（选格式 / 下载日志）→ 当前下载状态卡

- **下载页**：进行中卡片（大卡片、模糊缩略图铺底、进度条、取消）+ **队列分组**（可单条移除）+ 历史卡片（白字标题/作者、时长左下、日期右下、圆角方形播放键、右上删除）+ 筛选 chip（全部/视频/音频）；清空记录
- **前台 Service + 通知栏**：切走 App/锁屏继续下载；通知显示 进度·速度·剩余·**队列 N**，带取消按钮；完成/失败用独立通知 id（不被下一个任务顶掉）
- **默认存系统相册**：MediaStore 发布到 `Movies/VideoDL`（**已移除 `MANAGE_EXTERNAL_STORAGE`**，只需 Android 9 及以下的 `WRITE_EXTERNAL_STORAGE`）；发布成功后删除 App 私有副本
- **分享直达**：`ShareReceiver` **自己直接启动下载**（不再依赖 MainActivity 存活），并回填链接 + 抓取信息
- **下载队列**：一次跑一个，其余排队（上限 5）；「停止」清空队列；关键状态写 logcat（`queued` / `dispatch next from queue` / `queue empty`）

## 6. 常用命令 / 技巧

```powershell
# 构建 + 单测 + 装机
cd VideoDL-Android
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug --console=plain
adb install -r app\build\outputs\apk\debug\app-debug.apk

# 真机测试产物编码（关键验证手段）
adb pull "/sdcard/Movies/VideoDL/<文件名>" "$env:TEMP\x.mp4"
ffprobe -v error -show_entries "format=format_name,duration:stream=codec_type,codec_name,width,height" -of default=noprint_wrappers=1 "$env:TEMP\x.mp4"

# 用分享直达触发下载（最稳的自动化入口，不依赖界面点击）
adb shell am start -a android.intent.action.SEND -t text/plain --es android.intent.extra.TEXT "<url>" -n com.videodl.app/.ShareReceiver

# 把 App 拉到前台（CLEAR_TOP，可清掉顶上的播放器）
adb shell "am start -n com.videodl.app/.MainActivity -f 0x04000000"

# 看应用日志（队列等关键状态已写 logcat）
adb logcat -d -s VideoDL:V python.stdout:V python.stderr:V
```

**踩过的坑**
- Gradle 需要写 `~/.gradle`（工作区外）→ 沙箱下要放开文件权限
- `uiautomator dump` 对 Compose 会把文本**合并成一个节点**：判断"某文字是否存在"可靠，靠它解析控件坐标不可靠；固定坐标点击更稳（首页输入框 (540,377)、初始态「抓取信息」(420,555)、底部导航 y=2310）
- 下载完成会**自动打开系统播放器**（`autoOpenFile` 默认开），播放器会占满屏幕 → 截图前要先 `am start -CLEAR_TOP` 把 App 压回前台；锁屏后无法截图
- `read_image` **取决于当轮模型**：写这份文档的会话里可用，后续会话（deepseek-v4-flash）**不可用**。不支持图像时改用像素/几何断言，或把截图发给用户看

## 10. 重要发现：安卓端的「编码兜底」是死代码（后续会话查出）

**结论：`_ensure_importable()` 在安卓上永远失败，转码从来没成功过。**

证据（对 `app/src/main/jniLibs/arm64-v8a/libffmpeg.so` 的静态分析）：

```
configuration: --disable-gpl --disable-nonfree --enable-version3
               --disable-everything ... --enable-encoder=mjpeg ...
```

- 完整开关里**只有 `--enable-encoder=mjpeg`**：没有 `libx264`、没有 `h264`、
  没有 `libopenh264`、没有 `h264_mediacodec`，**也没有 `aac`**
- 而 `ytdlp_bridge.py:237` 请求的是 `-c:v libx264` / `-c:a aac` →
  ffmpeg 直接报 "Unknown encoder"，两次降级尝试都失败 → 走
  `[警告] 两种参数都失败，已保留原文件`
- 之前文档里写的「`libffmpeg.so`（含 libx264）」**是错的**。`FFmpeg version n8.1.2`
  里确实有 `x264 - core %d`、`libx264-lossless` 这类字符串，但那来自 **H.264 码流解析**
  （`--enable-parser=h264` 带的），不代表有编码器；`x264_encoder_open` 等
  libx264 API 符号一个都没有
- `--disable-gpl` 是决定性的：FFmpeg 的 configure 在 `--enable-libx264` 而没开 GPL 时
  会**直接 die**，所以这个二进制不可能含 libx264。打印的 `configuration:` 行是
  原样回显命令行参数，里面没有 `--enable-libx264`

**这不是"忘了接线"，是许可证约束的必然结果**：libx264 是 GPL，所以任何能闭源商用的
ffmpeg 构建都不会包含它。之前那句"含 libx264"很可能是把**桌面端**的 ffmpeg 8.1.1
（系统 PATH 里的 Gyan 完整版，确实有 libx264）误当成了安卓端这份。

**不受影响的**：合并音视频流走的是 `-c copy`，不需要编码器，所以日常下载正常。
**受影响的**：格式只提供 HEVC/AV1 时，App 无法转成 H.264 → 相册/剪映可能打不开，
而这正是这个功能本来要解决的场景。

**修法**（重建 `libffmpeg.so`，二选一）：
- `--enable-libopenh264`（BSD）软件编码，或
- `--enable-jni --enable-mediacodec --enable-encoder=h264_mediacodec`（Apache-2.0，
  手机硬件编码，快得多）+ 原生 `aac` 编码器

**待确认**：以上是静态分析，还没在真机上跑过 `ffmpeg -encoders` 核实。
手机连上后第一件事就该做这个。

**和许可证的关系（用户在做闭源收费产品的决策）**：用户明确想做闭源 + 收费，
所以**不能**用 GPL 的 libx264，也不能抄 YTDLnis（GPL-3.0）的代码。合法组合是：
自己的 Compose 界面（版式属于想法，不受著作权保护）+ yt-dlp（**Unlicense，公有领域**）
+ LGPL 的 ffmpeg（需附许可证文本、允许替换该库）。详见 README 的「已知问题」。
